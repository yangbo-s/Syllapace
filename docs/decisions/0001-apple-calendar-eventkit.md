# Apple Calendar 接入采用 EventKit

状态：已采纳，2026-11-04。

## 背景

Syllapace 是用户自行运行、自行配置 Canvas token 和模型 key 的原生 macOS 开源应用。桌面卡片借鉴 Still Today 的交互思路；Apple Calendar 用于展示和提醒已确认的学业事件。

## 决策

通过 EventKit 维护独立的 `Syllapace` 日历，持续同步事件的新增、改期和明确取消。该日历是可编辑的普通日历，不是只读 ICS 订阅。此方案无需提供本机 HTTP 订阅服务。

- 默认使用「在我的 Mac 上」的本地日历来源。如果系统没有可用的本地来源，引导用户在 Calendar 中创建本地日历，或明确选择其他可写来源；不自动改用 iCloud。
- 用户主动启用日历连接时，说明用途并请求完整日历访问权限。持续定位、更新和删除已写入事件需要该权限，单纯的写入权限不足以完成同步。
- 系统授权范围覆盖用户日历；应用逻辑只操作所绑定的专用日历及本应用管理的事件。拒绝或撤销权限后，应用内日程与审核仍然可用。
- 仅同步已确认且日期已确定的事件。未解决的日期歧义和来源冲突留在应用内审核。
- 保留日期精度与时区；日期型事件写为全天事件，不编造截止时刻。

## 同步规则

1. Syllapace 的稳定事件 ID 独立于 EventKit 标识。持久化日历绑定、事件映射及上次成功写入的内容；改期更新原事件，不重复创建。
2. EventKit 标识失效时，依据可核验的应用归属标记进行重关联。无法确定身份时展示待处理状态，不仅凭标题或日期覆盖事件。
3. 发布前比较上次写入内容与 Calendar 当前内容。用户在 Calendar 中编辑或删除事件时，记录差异并交由用户处理，避免无提示覆盖或重新创建。
4. 来源不可访问、同步失败或列表暂时缺项不等于取消。只有明确确认的取消或用户操作才触发日历删除。
5. 写入失败保留待同步状态；写入成功后才更新映射与同步记录。重新连接后对账，并保证重复同步不会制造副本。
6. 应用退出后，已保存事件由系统日历保留；后续来源变化在应用再次运行并同步时处理。

## 后续实现的验收重点

- 授权、拒绝和撤销权限的行为正确。
- 重复同步不新增副本，改期更新原事件，明确取消只移除对应的受管事件。
- 外部编辑、删除和来源暂时失联不会导致静默覆盖或误删。
- 全天事件、带时区的事件在 Calendar 中显示正确。
- 默认本机存储；选择其他账户必须由用户明确决定。

本记录仅确定方案，尚未实现或验证系统日历集成。
