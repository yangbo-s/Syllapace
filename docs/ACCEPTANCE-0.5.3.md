# 0.5.3 整理证据与时间线验收

对应 [计划](PLAN-0.5.3.md) R531–R536。用户明确授权的 8 份不同 Canvas syllabus / 公告正文只发送到已配置的 `api.openai.com`、`gpt-6.1-sol`；本次共 10 次 HTTP 请求，其中 2 次是修复后重验原来的两份 syllabus。结果只写隔离副本。正文、凭据、请求与响应不进入 Git、安装包或公开报告。

## 结果与根因

初次实际模型验证 7/8 通过，其中一份因模型拼接原文引用而被严格校验拒绝；另一份 PDF 的 5 个作业与博客日期无法由拆散的月份标题、日/星期行证明。增加确定性表格证据后，同一组两份 syllabus 各提取 5 个作业与 1 个博客日期，全部通过原文和日期校验；未放宽验证来接受猜测。`11:59:59pm` 保留秒数与 PM，明确的 Canvas 当前截止时间覆盖初步 syllabus 日程。

最终 8/8 资料整理通过，0 处理失败。重新读取全部 8 份命中缓存，运输层硬性禁网时 0 HTTP 请求，事件、来源、整理记录与选择集合语义不变。日期缺失与来源冲突仍需确认：隔离资料剩余 14 个待补充来源，以及 1 项真实冲突（同一博客在 HTML 与 PDF 中分别写 12 月 24 日与 12 月 3 日）。不把冲突当两个已确认事项，也不替用户决定哪份正确。

同一作业根据明确任务身份合并，保留来源、别名、release 与用户编辑；旧 `document-` ID 经重新整理后仍参与去重。官方课次的 Lecture / Recitation 角色由明确且完全匹配的 syllabus 时间补足，因此模型不再重复生成整学期课程时，recitation 取消通知仍有效。纯成绩公告不因无关作业上下文变化而重复整理；既有无实际日期差异的提案在新证据完全一致时清除。

时间线错误在真实 WKWebView 复现：左栏内容高与视口同为 585 px，右栏横向滚动条使视口仅 568 px。右栏 `scrollTop=17`、左栏 `scrollTop=0`，对应行差 -17 px。现在按实际原生滚动条尺寸为左侧内容保留等量底部空间，恢复相同滚动范围；没有硬编码偏移文字或修改事项日期。密集行、顶部/中部/底部及仅滚动条产生溢出的边界均纳入回归。

真实窗口验收还发现“需要补充”页高 CPU：采样显示过滤每个事件时都重新计算 `unresolvedEvents`，重复扫描全部来源。改为每次过滤前计算一次 ID 集合，避免按事件数量重复投影。

## 限制与发布

官方检索仍限 CMU Pittsburgh 的已支持完整学期课程；不使用其他学期的时间补猜。8 份资料验证不是全量课程资料的通用准确率。应用仍为 ad hoc 签名，未做 Apple Developer ID 公证。实际安装与升级由用户自行验证；不修改其更新计时或偏好。

本地发布候选 `build/releases/0.5.3-shipping/` 已通过更新签名、内嵌公钥、arm64、版本、ZIP 应用签名和 DMG 完整性校验。版本 **0.5.3 / build 10**；本机已安装 **0.5.2 / build 9** 的指纹已保存，发布后只读核对。评分及公开回读结果将在发布后补记。
