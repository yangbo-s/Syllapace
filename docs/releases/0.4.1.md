# Syllapace 0.4.1

Canvas tokens and model API keys now stay in a **local file by default**. Normal local reads, saves, and background sync do not access macOS Keychain. Keychain remains an optional setting.

- **Choose your storage** in Settings → General → Credential storage: Local file or macOS Keychain. Canvas and Models settings now describe the selected-storage workflow accurately, in English and Simplified Chinese.
- **Import existing credentials explicitly.** Upgrades start in Local mode without reading old Keychain entries. Choose Import from Keychain… or enter your token and API key again. Import can ask for macOS permission; existing local keys and explicit deletions take precedence, and the original Keychain records stay untouched. Failed or cancelled imports commit no partial results.
- **Switch without losing saved local keys.** Moving to Keychain copies all local credentials before committing the change and removing the plaintext copies. If a write fails, Local stays active with its values intact; already-written Keychain copies may remain. Returning to Local never accesses Keychain; import or re-enter keys afterwards.
- **No repeated background alert for a missing Canvas token.** Background sync leaves an informational status instead; an explicit sync still explains how to reconnect.

## Local storage and updating

Local credentials live separately from course data at `~/Library/Application Support/Syllapace/Credentials/credentials.json`. The directory uses `0700` and the file `0600` permissions, with atomic writes. **The file is not encrypted:** programs running as your macOS account may read it. Local credentials are excluded from the course archive, its backups, exports, and the embedded web workspace. Optional Keychain mode retains macOS access controls and may still display authorization prompts.

This release is **0.4.1, build 6**. Use **Syllapace → Check for Updates…** to test the update in your existing installation. Automatic checks run roughly every 24 hours while the app is open, with installation after confirmation. The Sparkle signing identity and library schema 4 are unchanged.

Requires **Apple Silicon and macOS 26+**. The DMG supports manual installation; the ZIP is the signed Sparkle update archive. Checksums are in `SHA256SUMS`. The application remains **ad hoc signed and not notarized by Apple**; see [Apple’s per-app opening instructions](https://support.apple.com/en-us/102445) for a first-launch block.
